<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| golden set → eval score | The score is only as honest as the golden set (see 02-04 validation) |
| recorded drafts → pipeline | drafts.jsonl is an untrusted input file: it is parsed and schema-validated, never executed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-17 | Repudiation | Reporting only F1 hides a recall or precision regression | mitigate | score() exposes precision and recall as distinct fields; the CLI prints them separately every run (Tasks 1,5) |
| T-02-18 | Tampering | ~~GPU nondeterminism makes a close bake-off unreproducible~~ — RETIRED with the local model. The replacement risk: a *recorded* drafts artifact could drift from the code that produced it | mitigate | Superseded by the replay design: drafts.jsonl is committed and content-keyed, so a run is exactly reproducible by construction (no seed/temperature/GPU variance in the pipeline at all). chunk_key is content-derived, so drafts recorded against stale chunk text fail to resolve and surface as unextracted chunks rather than silently mismatching (Task 2) |
| T-02-19 | Spoofing | Extracting from golden_set.json instead of the source chunks would fabricate a ~100% score and destroy the accuracy signal | mitigate | Explicit honesty constraint in Task 4; verbatim spans must ground by string match against real page text, which a transcribed answer key would not reliably satisfy |
| T-02-20 | Denial of service | A malformed/truncated drafts.jsonl silently yielding zero requirements would look like "clean run, no requirements found" | mitigate | load_drafts raises on a malformed line with its line number; missing chunks are counted and printed as unextracted chunks (Tasks 2,3) |
</threat_model>
